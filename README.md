# Pia

**Point a phone at sheet music. Hear it play.**

Pia reads printed piano music from a photo and plays it back, so you can hear the piece
you are trying to learn — slowed down, looped, one hand at a time, with the keys lighting
up as they sound.

It is a static site. There is no backend, no account and no upload: the photo is read on
your own device and never leaves it.

## Try it

```bash
npm install
npm run dev
```

Then open the URL it prints. On a phone, tap **Scan sheet music**; on a desktop there is
no camera worth using, so the same button falls through to a file picker. Or press one of
the built-in pieces to hear something immediately.

## How it works

A photo of a page becomes a playable score through a classical optical-music-recognition
pipeline, written from scratch and running in a Web Worker:

| Stage | What happens |
| --- | --- |
| Threshold | Adaptive (integral-image mean) — a phone photo has a lighting gradient a global threshold cannot survive |
| Denoise | Binary majority filter, gated on actually finding grain, so clean scans are untouched |
| Scale | Vertical run-length modes give staff line thickness and staff space — the one unit everything else is expressed in |
| Deskew | Shear search maximising the spikiness of the row-ink profile |
| Staves | Row projection peaks grouped into fives, then into systems by the gap between them |
| Staff removal | Thin vertical runs *with* long horizontal runs, which keeps stems, noteheads and the dot beside a note |
| Symbols | 8-connected components, then a window scan for noteheads scoring the ring between an outer and an inner window |
| Rhythm | Stems by column ink, beams and flags by bands beside the stem tip, augmentation dots by an isolated blob |
| Pitch | Staff position plus clef, key signature and any accidental written beside the note |
| Timing | Durations accumulated per staff and reset at every barline, so a misread cannot drift the hands apart |

Audio is synthesised rather than sampled: a stack of partials stretched by string
inharmonicity, each decaying faster than the last, over a filtered noise burst for the
hammer. A sampled piano would sound better and cost 5–50 MB, which would break the one
promise the app makes — that you open it and hear music.

See [`docs/SPEC.md`](docs/SPEC.md) for the product spec, the technology choices and what
is deliberately out of scope.

## What it is good at, and what it is not

It reads **clean printed music**, well lit, page flat and filling the frame. Chords,
ledger lines, beamed groups, accidentals, key signatures, dotted notes, rests and
multiple systems per page all work.

It does not read handwriting, and it ignores repeats, voltas, ties across barlines,
tuplets, grace notes and second voices on a staff. Key-signature detection is a
heuristic, so there is always a manual key selector.

Everything it gets wrong is fixable by tapping: the **Fix notes** tab is a piano roll
where you can change a note's pitch, length or hand, delete it, or add one.

## Development

```bash
npm test           # the recogniser's test suite
npm run lint
npm run build

npm run fixture    # render a page of music to .fixtures/sheet.png
npm run drive      # scan that page in a real browser, screenshots to .fixtures/
npm run pack       # fold the build into one self-contained .fixtures/pia.html
```

The recogniser is tested against pages generated by a small engraver
(`src/omr/__tests__/render.ts`) rather than against fixture images, so every test states
the notes it drew and the notes it expects back.

`npm run drive` needs a preview server running (`npx vite preview --port 4173`).

## Deploying

`npm run pack` inlines the stylesheet and script into a single HTML file. The Web Worker
already travels inside the bundle (`?worker&inline`), so the packed page fetches nothing
at runtime and can be served from anywhere — including hosts that serve one file and
block external requests.

Two things behave differently when the app is served that way, both deliberate: MIDI
export is withheld, because a sandboxed page cannot hand the viewer a file; and the
camera is usually refused, so **Scan sheet music** falls through to the photo picker.
Recognition, playback, practice and editing are unaffected.


`npm run build` writes a static `dist/` with relative asset paths, so it works from a
domain root or a project subpath unchanged. Pushing to `main` builds and publishes it to
GitHub Pages via `.github/workflows/deploy.yml`; enable Pages with source "GitHub Actions"
in the repository settings first.
